# Customer Experience Implementation

## Implemented

- Optional sequential WhatsApp list processing makes the first unfinished requested item the active question. It finishes product identity, variant and missing purchase quantity/unit before showing the next item, preserves every other line, and shows localized item progress. Available later items cannot silently bypass an absent first item. Initially exact complete lists retain grouped confirmation; selections, quantity answers and automatic advancement do not require new AI calls. Submitted-order proposals preview only the first category while keeping all proposed lines. Final review is structured text with catalog unit prices and line totals, not an invoice, stock reservation or packing promise.
- Opt-in media recommendations separate catalog-independent recognition from one compact, read-only agent question/shortlist over fresh matching products. The question appears above the photos; up to four real SKUs are ranked without changing quantities or authorizing submission. The recommendation prompt excludes the catalog taxonomy and unrelated listings. Text discovery remains separately gated.
- New multi-item requests after submission now show read-only product photos immediately. A current product tap starts all proposed lines, confirms only the chosen product and preserves every other amount or unknown quantity. Start this list remains available on the carousel; duplicate/stale taps cannot replace a newer list or alter an old submitted request.
- Voice decoding is single-thread bounded, with a 20-second deadline and unchanged 30-second/1 MB input limits. Audio identification has a 19-second SDK deadline within a 20-second runtime limit and 45-second work lease; the small recommendation call retains its 9.5/10-second deadlines. There are no hidden model retries. Provider failures retain safe HTTP/timeout codes and conservative billing holds.
- Unreadable attachments receive a short Tamil/Tanglish line plus bound browsing and shop-handoff buttons, never a fabricated recognition. Explicit English number-word dimensions such as one inch normalize to numeric catalog constraints without treating one blade as a dimension or supplying a missing purchase amount.
- Direct requests still work without a mandatory greeting menu. Greetings offer browsing, help and shop handoff.
- Exact product matches support grouped confirmation, followed by a full price-and-quantity review. Ambiguous matches still require selection; related items are not silently substituted.
- Item-specific editing preserves the other draft lines. Decimal quantities obey catalog increments. Keeping a list invalidates previous confirmation buttons.
- Request status reflects acceptance/rejection separately from payment and pickup readiness. Starting a new list preserves previous immutable requests and resets the active AI context.
- Customer handoff pauses assistant processing, retains the inbox and prioritizes the conversation for the owner. Authenticated manual replies are audited, revision-bound, idempotent and limited to the WhatsApp service window.
- Optional text discovery has a second, read-only recommendation stage over fresh catalog results. It cannot alter quantities or invent selectable product identifiers. Shared quota spacing is respected without holding a work lease.
- Optional WhatsApp photos and voice notes are durably recorded before acknowledgement, then privately downloaded, bounded and normalized. Media lease recovery rejects late results from an old worker. No new public attachment endpoint is exposed.
- Native preview prevents double submissions and unsupported attachments. Owner history includes scoped private media and product images.
- Discovery shows up to four actual catalog options, with exact matches first when supported. Carousel cards carry selection/confirmation and a bound More options menu for filtering, list editing, browsing and shop help. Multi-item confirmation pages retain all requested groups rather than truncating them to four.
- New requests after a submitted request remain read-only until a current displayed product choice starts a new list. Previous submitted requests are immutable.
- A new multi-item request after submission is saved as a read-only proposal, preserving each item and amount. A bound Start this list button opens the ordinary product/quantity checks in one tap. It never submits an order, and stale buttons cannot restore a newer proposal. Old submitted draft IDs, pending edits and pending-item memory are hidden from new model identification.
- Tamil spoken purchase amounts are distinct from dimensions: one blade requests quantity one; a one-inch pipe still requires a purchase amount. Read-only model assistance with a mislabeled next action is normalized only when there are no write operations, price query or conversation intent. Mixed proposals still fail validation.
- Photo recognition receives no catalog taxonomy or product suggestions. Visual family/department guesses cannot force unrelated inventory matches: canonical visible keywords, labels and supported filters feed deterministic search. A nail must not become a screw box when nails have no catalog listing.
- Native Gemini text/photo/voice understanding uses one identification call by default. Text receives a bounded taxonomy and compact context, not the entire catalog; deterministic SQL supplies real product facts. Voice/photo recognition excludes catalog listings, taxonomy and observed suggestions so available stock cannot replace the actual request. Photos receive only supported specification-key names; unsupported label attributes become keywords, not hard filters hiding valid products. Audio has a dedicated audible-speech contract and requires an original-language transcript in strict backend validation. Native generation uses JSON mode: the expanded response schema was rejected by Google during live testing. No local speech model or TTS is used.
- Product specification lookup recognizes equivalent explicit inch spellings (`12"`, `12 in`, `12 inches`, `12 inch`) without conflating different numeric sizes or millimetres.
- Optional read/typing indication is claimed once for one eligible pending message. Transient network/5xx attachment downloads retry once; permission/rate-limit failures, unsafe hosts and oversized files do not. Error codes omit private URLs, tokens and media bytes. The 75-second media lease includes the bounded download retry and raster normalization.

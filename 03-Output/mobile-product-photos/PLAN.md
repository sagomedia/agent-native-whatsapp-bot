# Mobile product photo uploads and bounded storage

Accept owner-selected product photos up to 10 MiB and optimize before upload. Sniff actual raster bytes rather than trusting Android file MIME labels; explain unsupported HEIF/RAW files. Preserve proportions/orientation and product details, never crop or upscale. Normalize a JPEG master at up to 1280 px and 500 KiB, with existing small catalog variants bounded independently. Keep the original only temporarily during processing; persist optimized catalog bytes only. Keep existing photos and form facts on failures and prevent save/suggestion races while preprocessing. Cover ordinary product add/edit, advanced product editor and batch import using one helper; customer voice/handwritten images and MCP upload limits retain their existing contracts.

Server normalization must enforce the catalog storage bounds even if a caller bypasses browser preprocessing. No destructive backfill or original-photo history purge; existing inventory/orders/media remain intact. Record conservative 3000-product storage including preview copies and retained proposal copies, database overhead and backups; 30 GB also contains application/runtime/customer media.

Verify real browser image encoding (large/high-resolution, empty/wrong MIME, portrait EXIF, transparency, repeated picks, failure), server output/storage limits and numeric/type guards. Run focused tests, integration suite, production build and required Python checks. Preserve the current deployed source and release through existing backup/rollback after validation.
